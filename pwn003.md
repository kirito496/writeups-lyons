# PWN#003 — Notes Vault (UAF + empoisonnement de freelist + system)

- **Auteur :** lyons
- **Cible :** `<HOST>:<PORT>` (Notes Vault, ELF x86-64 PIE)
- **Catégorie :** pwn
- **Flag :** `CTF{REDACTED}` (voir la règle de non-persistance des flags)
- **Fichiers fournis :** binaire ELF x86-64 PIE, non strippé, 21864 octets

## Mise en contexte

Un gestionnaire de notes interactif déroule un menu : Add, Free, Edit, View. L'exécutable, ELF x86-64 PIE, conserve ses symboles. La libc n'accompagne pas les fichiers fournis ; le serveur distant tourne néanmoins avec la même glibc 2.42-13 que les défis précédents.

L'exécutable embarque un allocateur de pool artisanal — fonctions `palloc` et `pfree` écrites à la main — adossé à une freelist à pointeur encodé (mangle).

## Phase de reconnaissance

### Mécanismes de défense

| Protection   | État                          |
|---|---|
| Canary       | Activé                        |
| NX           | Activé                        |
| RELRO        | Full                          |
| PIE          | Activé                        |
| Symboles     | Présents (binaire non strippé)|

### Fuite de la base PIE

Dès le démarrage, un message de debug dévoile une adresse de `main`. L'offset de `main` valant `0x1af8`, la base PIE se calcule par `main_leak - 0x1af8`.

### L'allocateur de pool

Les demandes de taille 32 passent par un pool sur mesure équipé d'une freelist. Le pointeur suivant de cette liste est brouillé par la fonction `mangle` :

```
mangle(ptr, node) = ptr XOR rol(node, 13)
```

Quand un seul chunk occupe la freelist, le décodage du pointeur encodé se réduit à `ror(encoded, 13)`, puisque `ptr = 0` (bout de liste) :

```
mangle(0, chunk) = 0 XOR rol(chunk, 13) = rol(chunk, 13)
```

### Anatomie d'une note

Chaque note agrège :
- un pointeur de formatage (`fmt`) : fonction invoquée lors de `view_note` ;
- un pointeur de contenu (`content`) : argument transmis à la fonction de formatage.

`view_note` se borne à exécuter : `call [note->fmt](rdi = note->content)`.

## La faille

### Use-After-Free

`free_note` relâche le chunk de la note, mais **omet de réinitialiser `notes[idx]` à NULL**. Après un `Free`, `Edit` comme `View` demeurent utilisables sur la note libérée.

### Combinaison des primitifs

1. **View après Free** : lire le chunk libéré expose le pointeur de freelist encodé ; `ror(encoded, 13)` en tire l'adresse du chunk.
2. **Edit après Free** : écrire dans ce chunk libéré modifie le pointeur de freelist, ouvrant la voie à un empoisonnement qui détourne la prochaine allocation vers une adresse arbitraire.
3. **Callback de formatage** : `view_note` invoque `[note->fmt](note->content)` ; dès que les métadonnées de la note sont écrasées, `rip` et `rdi` passent sous notre contrôle.

## Exploitation

### Étape 1 — Fuite du heap puis empoisonnement de la freelist

1. Création de la note 0 (taille 32).
2. Libération de la note 0 (`Free(0)`).
3. Lecture de la note 0 (`View(0)`) : le chunk fraîchement libéré héberge `mangle(0, chunk) = rol(chunk, 13)` ; un passage par `ror(encoded, 13)` restitue l'adresse du chunk.
4. Édition de la note 0 (`Edit(0)`) : y déposer un pointeur encodé qui réoriente la freelist vers les métadonnées de la note 1 :

```
target       = PIE_base + 0x40e0 + 24   (metadonnees de la note 1)
encoded_next = target XOR rol(chunk, 13)
```

5. Aux deux allocations qui suivent :
   - la première rend le chunk d'origine ;
   - la seconde livre la cible empoisonnée (métadonnées de la note 1).

### Étape 2 — Fuite libc par puts@GOT

L'allocation tombant sur la cible grave dans les métadonnées de la note 1 :
- `fmt` = `puts@PLT` (adresse déduite de la base PIE) ;
- `content` = `puts@GOT` (adresse déduite de la base PIE).

`View(1)` déclenche alors `puts(puts@GOT)`, et l'adresse résolue de `puts` côté libc s'imprime.

```
libc_base = puts_leak - 0x82060
```

Cet offset `0x82060` désigne `puts` au sein de la glibc 2.42-13 repérée sur le serveur distant ; l'alignement page a été contrôlé.

### Étape 3 — Passer par system("/bin/sh")

Toujours par le même empoisonnement des métadonnées :
- `fmt` = `system` (`libc_base + 0x54790`) ;
- `content` = l'adresse d'un chunk sous contrôle, porteur de la commande.

Le chunk est garni d'une commande chargée de lire le flag. Un `View(1)` fait partir `system(commande)`, et le flag jaillit dans la sortie.

### Localisation du flag

Côté serveur distant, le flag loge dans la variable d'environnement `FLAG=`.

## Résultat

Un shell est tombé par `system()`, et le flag a été récupéré puis soumis avec succès.

```
CTF{REDACTED}
```

## Obstacles rencontrés

- **Encodage `mangle`** : le pointeur de freelist passe par `XOR rol(node, 13)`. Négliger la rotation rend l'empoisonnement stérile. Validez d'abord avec un chunk isolé dans la freelist (cas simple où `ptr = 0`).
- **Freelist mono-élément** : le décodage par `ror` ne fonctionne tel quel que si le chunk est seul dans la liste (son successeur vaut `NULL`). Plusieurs chunks cohabitants ? Il faut alors connaître le pointeur suivant pour décoder.
- **Offset du pool** : les métadonnées des notes siègent à `PIE_base + 0x40e0 + 24`. Une erreur d'un seul octet sur l'adresse cible produit une corruption parfaitement silencieuse.
- **Alignement libc** : les offsets de `puts` (`0x82060`) comme de `system` (`0x54790`) doivent être vérifiés face à la libc distante ; la libc locale peut raconter autre chose.

## Enseignements

1. **UAF = lecture + écriture d'un coup** : un use-after-free qui conserve le pointeur dans le tableau offre simultanément un canal de lecture (fuite du chunk) et un canal d'écriture (empoisonnement de la freelist).
2. **Allocateurs maison** : la freelist encodée d'un pool artisanal ajoute un vernis de protection, qui s'efface dès que l'adresse du chunk est connue — précisément ce que livre la fuite UAF elle-même.
3. **Callbacks entreposés en mémoire** : un pointeur de fonction (`fmt`) stocké à côté des données utilisateur forme un vecteur RIP control classique. La combinaison UAF + callback débouche sur l'exécution arbitraire.
4. **Un exploit, deux usages** : la même mécanique (empoisonnement de freelist + callback) alimente d'abord la fuite libc, puis l'appel à `system`. Recycler le primitif allège nettement l'ensemble.
